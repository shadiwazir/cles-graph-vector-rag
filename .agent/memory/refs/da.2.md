# da.2 Docling trial (2026-11-16, side question from user)
- User asked: if we used Docling instead of the LLM for extraction, what would change, would it work at all. Clarified: Docling is a layout-aware PDF->structured document converter (parsing), not a semantic extractor; it could compete with PyMuPDF in the parse stage, not with the LLM extract stage (parties, citation treatment, outcome, stage cuts).
- Tried docling 2.150.0 in an isolated venv (scratchpad docling_env), CPU, on 724 (4 pages), 719 (28), 709 (31): 25 s, 27 s, 31 s per document (models already loaded; first run downloads layout models). PyMuPDF takes about 0.1 s.
- Strengths seen: removes "Page: n" headers; finds headings incl. sub-headings with levels (719: 15 section headers incl. "1. Minimizing...", our regex only finds top-level all-caps); labels footnotes separately (3 per doc) although it places the footnote text in the middle of paragraph [1] in reading order; OCR for scanned PDFs (not tested; no scanned sample).
- Weaknesses seen for our need (paragraph-number citations): marker loss/merge: 719 lost line-start markers for [13], [16], [17] (¶17 text not found at all); 709 lost [14], [15], [53 merged mid-line], [54 text not found], [69], [1997]; 724 perfect. Our PyMuPDF parser reconstructs all numbered paragraphs (719: 76/76, 709: 86/86) with the pack regex. Some paragraphs came out as list items ("- [2]"). Header lines merged into one line ("CITATION ... DATE ... DOCKET").
- Cost: torch + layout models, about 25-30 s/doc on CPU, so 10k docs would be roughly 70-80 CPU-hours (GPU much faster); PyMuPDF about minutes.
- Recommendation given: keep PyMuPDF default; consider Docling only as optional fallback for scanned/low-text PDFs (parser currently rejects them) once the real corpus shows how many exist, behind a Parser interface. Not implemented. Web search found only the 2024 technical report (layout model RT-DETR on DocLayNet, TableFormer, optional EasyOCR); I could not confirm 2026 features such as VLM conversion or any semantic extraction.
