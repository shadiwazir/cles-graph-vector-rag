# gr.3 Local LLM trial with Ollama (2026-11-12)
- Ollama 0.33.2 running at localhost:11434, models gemma3:1b, gemma3:270m, qwen2.5:1.5b (user's). Works with our OpenAI-compatible client via env: LLM_BASE_URL=http://localhost:11434/v1 OPENAI_API_KEY=ollama LLM_MODEL=... (no code change needed). Ollama default context is small, so I created two derived models with num_ctx 16384 (cles-qwen2.5-1.5b-16k, cles-gemma3-1b-16k; created by me, can be removed with `ollama rm`).
- Results on 15 sample decisions (concurrency 1, GTX 1050 3GB): qwen2.5:1.5b 5/15 valid, ~26 min; gemma3:1b 3/15 valid, ~8 min; gemma3:270m not tried.
- Invalid reasons: schema near-misses (null for optional int, enum case 'Appellant', 'followed, cited' in single-valued enum, list instead of string, enum 'lower_court_decisions'). Valid ones still semantically weak: outcome labels outside our list, judges often empty, few citations, gemma outcomes meaningless.
- Changes made: parser-known fields (case_id, title, decision_date) override model output (pack.yaml known_fields); extractor `tidy` (drop nulls, enum case-insensitive); outcome enum added to extraction_schema.json (was free text) + test that it equals outcomes.yaml.
- Conclusion: pipeline mechanics validated locally; 1B-class models are not adequate for extraction quality. Need a stronger model: frontier API (OpenAI small model: ~87k input tokens for the 15 samples) or a 7-8B local model (does not fit the 3GB GPU; CPU slow). Local junk extractions deleted from DB.
