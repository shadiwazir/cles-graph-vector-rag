## Pilot result and mistakes (2026-11-13)
- Setup on the pod: the image's torch got replaced in the venv (torch 2.15 cu132 first, then 2.14.1 with unsloth 2026.11.4; trl 1.15.0, transformers 5.17, datasets 4.8.5, bitsandbytes 0.50.2). Installing unsloth in the same uv command as the newer pins resolved to unsloth 2024.8 (no bitsandbytes, import failed): install it in a second step (now in gpu_setup.sh). Our code works with trl 1.15.0.
- Pilot (3 steps, config pilot.yaml = poc + max_steps 3): status ok, train_loss 1.452, eval_loss 1.297 on 4 eval examples (meaningless at 3 steps), 44 to 52 s per step of 16 sequences (about 118k tokens), so about 2.4 to 2.7k tokens/s; no OOM at 12288 with batch 1; total 153 s in MLflow. Padding-free batching auto-enabled. Unsloth loaded its pre-quantized `unsloth/Qwen3-8B-unsloth-bnb-4bit` (about 6.5 GB), not the 16 GB base. 359 examples x 2 epochs / 16 = about 45 optimizer steps, so the full run is about 35 min (about $0.65) at pilot speed. The runbook's "100-step pilot" is longer than the whole run on this dataset: use 3 steps.
- Mistake 1: I wrapped the first pilot launch in `/usr/bin/time`, which is not installed on the pod, so it never started and the pod idled about 25 min (about $0.45); my monitor pattern did not match that error.
- Mistake 2: the second wait used `pgrep -f` inside the ssh command, which matches its own command line, so the wait never ended after the pilot finished and the pod kept billing until the user noticed. Fix: `gpu_setup.sh run/wait` using a `<name>.exit` marker file. Rule for next time: wait on a file or exit code, never on pgrep -f over ssh; match error strings too.
- Mistake 3 (user noticed): the model downloaded to /root/.cache (container disk, erased on stop) because non-interactive ssh does not read .bashrc, so HF_HOME was unset. Fix: /workspace/env.sh sourced by every command; cache copied to /workspace/.cache/huggingface (7.1 GB).
