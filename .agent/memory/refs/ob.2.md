# ob.2 Observability (ADR 0007)
User wants full observability beyond MLflow. User tried Langfuse, Phoenix, LLM-as-judge, Jev (TypeSafe hosted typed-judge model). Phoenix accepted; Jev only for public/synthetic data, optional judge backend. Confidentiality concern raised by me: lawyer text in telemetry and external generator.

## Licence research (user, 2026-11-14, PDF "Phoenix Local Container Licensing", third-party sources)
- Phoenix server (arize-phoenix) and evals library: Elastic License 2.0 (source-available, not OSI). Free to self-host, no keys, no feature gates; restriction: no hosted/managed service for third parties. Client and OTel packages (arize-phoenix-client, arize-phoenix-otel): Apache 2.0 (relicensed Nov 2025; conda-forge metadata stale). Patent notice IP_NOTICE exists (not inspected).
- Dynatrace announced the Arize acquisition 13 Aug 2026 ($915M) and closed it 1 Oct 2026; says Phoenix stays open source; roadmap risk only.
- arize-phoenix 21.0.0 (29 Oct 2026): authentication on by default for non-loopback hosts (Docker sets PHOENIX_HOST=::), daily price-table fetch from GitHub (PHOENIX_ALLOW_EXTERNAL_RESOURCES=false or PHOENIX_DISABLE_MODEL_COST_AUTO_UPDATE=true disables), Python >= 3.11. Default retention is infinite (PHOENIX_DEFAULT_RETENTION_POLICY_DAYS). Our image is pinned at version-20.27.0 (no auth change).
- Decision: keep Phoenix (internal PoC, never exposed). Compose: UI bound to 127.0.0.1, external resources off, 30-day retention. Fallbacks if needed: MLflow Tracing or Opik (Apache 2.0). Roles agree with the research: MLflow = training/eval runs and model registry; Phoenix = request traces and LLM-judge evals.
- User principle (2026-11-14): MLflow, DVC and the observability stack are part of every change in this PoC, to measure, compare and evaluate progress; they must not wait for a release. The project will never be released or public: it is a PoC and preparation for another project.
