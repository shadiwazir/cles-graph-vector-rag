- Estimate given to the user (scaled linearly from the 15-decision sample; OpenAI prices from third-party sites, GPU speed assumed): extraction 100 x $0.014 = about $1.5 to 3 (budget double for prompt tweaks); targets about 390 examples x $0.009 = about $3.5; baseline answers for about 40 eval examples under $1; GPU about $5 to 20 (2M tokens per epoch, 6M for 3 epochs, 1 to 2 h training, plus pilot, setup and 1 to 2 h serving for evaluation). Total about $15 to 30, API part about $5 to 8. Full corpus: about $500 data plus $30 to 50 per GPU epoch (docs/06).
- Local GPU (3 GB) cannot train an 8B QLoRA. Cheaper PoC option: a 24 GB card at roughly $0.3 to 0.5/h with a smaller base (Qwen3-4B); not verified.
- What 100 files can show: pipeline works end to end; the fine-tune learns JSON format, stage handling, citing only from supplied context, hedging on weak evidence. What it cannot show: domain accuracy (about 40 eval examples gives roughly +-15 points on outcome accuracy; mostly qualitative); rich retrieval (in the 15-sample run 24 of 59 examples had no authorities; random decisions rarely cite each other).
- Selection advice: a topical cluster across several years beats a random sample (shared statutes, issues, citations give the graph, date filter and evidence calibration something to do). The user's folder is mixed criminal and civil over 2020 to 2026, so the time split has a real range.
- Ways to cut cost further: two stages per decision instead of four; provider batch API (about half price); smaller base model; stop the rented machine immediately after each step.
- Staging suggestion: 100-file PoC first; only if promising, about 1,000 files (about $150) before the full 10,000.
- Cheaper middle option if the fine-tune is skipped: compare base model plus retrieval against the OpenAI baseline.
- Run playbook and automation: `scripts/pipeline.sh`, docs/07-run-playbook.md (see pl.2).
