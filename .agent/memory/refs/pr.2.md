# pr.2 Web console as the landing page (ADR 0020), 2026-11-14

- User request: the main page of the project, facing (imaginary) clients, shaped as if a ready product: a simple interface to ask questions to the expert system (the fine-tuned model) with answers and routes; tabs or menus to the other parts: the results explorer and the sub-systems (Grafana, MLflow, ...). The user decides about the next GPU run after this is done. The user also clarified: "I am not a lawyer" (see labels below).
- Built: cles/console/app.py (extends the advisor app, adds explorer routes, /api/info, /api/status), static console.html/css/js (Ask, Results explorer, Platform, About), advisor and explorer create_app refactored (page_route), settings grafana_url/phoenix_url/prometheus_url, compose: MLflow `--x-frame-options NONE`, Grafana embedding plus anonymous Viewer, all tool ports on 127.0.0.1, pipeline step `console`, tests/test_console.py (6). `scripts/pipeline.sh` keeps a command-line ALLOW_EXTERNAL_GENERATOR (the .env value had overridden it).
- Verified: endpoints with the real stack (107 decisions, 8 services responding), an advice call through the console, the page script with a DOM stub on real responses. Not verified in a real browser; I could not view it.
- Default model today: the OpenAI baseline (gpt-5.4-mini) until the fine-tuned model is served on a GPU (vLLM and an SSH tunnel are not done). The page says which model answers.
- Labels: the user is not a lawyer, so their labels are not legal opinions. A non-lawyer can judge faithfulness (is a claim in the shown passages?) only if the explorer shows the retrieved passages (it does not yet) and readability; usefulness and legal correctness need a lawyer. The judge stays uncalibrated, and the lawyer-review gate is not performed in this PoC.
